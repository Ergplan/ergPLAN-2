## D. Sizing from the user's own profiles and answers

- Generation profiles: the user can give a solar and a wind profile (hourly or 15-minute, one year, as CSV; per MW or
  for a stated capacity). Validate them (length, units, gaps, a capacity factor that is physically possible), store
  them with `provenance = measured` or `stated` and a sha256, show the CUF they imply, and use them in settlement and
  the optimizer in place of the library curve. A run pins the profile it used.
- Consumption profile: when there are only bills, ask what the bills do not say — shifts and their hours, the weekly
  off, seasonal shutdowns, large loads and when they run, the power factor, planned expansion, the roof and land
  available, the contract demand intended. Each answer is a `client_stated` value that the profile synthesis uses and
  the report shows. A measured 15-minute file replaces the synthesis.
- The transition plan: from today's bill to a stated target (a share of renewable energy, or the lowest cost), in
  phases the client can act on (rooftop first, then open access, then storage), each phase with its capacity, cost,
  saving, the rule that binds it, and what must be signed or applied for. Every figure a `SourcedValue`.

## E. The ergPLAN 2 MCP server

So that a bill dropped into Claude (the app or Claude Code) gets a savings analysis and a sizing after a few questions.

- Served by the API at `/mcp` (streamable HTTP), in `ergplan/mcp/` (a new folder: add it to `docs/architecture.md`).
  It calls the same functions as the screens and computes nothing of its own. Invariants hold: billx is the only bill
  reader, no model decides a number, every figure comes back with its source.
- Tools, typed: `read_bill` (the bill goes to billx; returns what was read and what needs confirming),
  `confirm_field`, `list_questions` (what is still missing, from part D), `answer`, `add_generation_profile`,
  `todays_cost`, `landed_cost`, `run_sizing` (returns "running" and a status tool when it takes more than a few
  seconds), `get_plan`, `transition_plan`, `state_rule_book`, `share_link`.
- Server instructions tell Claude to ask the open questions one or two at a time before sizing, to state numbers only
  from tool results, and to say which figures are assumed.
- If Claude cannot hand a file to a tool, `read_bill` returns a one-time upload link; test which works in claude.ai and
  in Claude Code, and say so.
- Access: the same administrator sign-in as part B (OAuth for the connector, backed by that account). It is never open
  to anyone who only has the address.
- Done when: with the connector added in claude.ai, one assumed Uttar Pradesh bill goes in, the questions are asked, a
  solar profile is supplied, and the answer equals `tests/e2e/test_up_assumed.py`'s figures for the same inputs; every
  tool has a test; the person is told the address to add as a connector.
